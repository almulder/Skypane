Add a second tablet

From a new tablet out of the box to a working Skypane panel — about 20 minutes. In this guide your server is 192.168.1.50 (with Docker: 192.168.1.20:8088 — add :8088 everywhere); the example panel is called Office (use your own name).

0What you need

  • The tablet (any Android tablet works; the same PoE wall-tablet model as the kitchen also gets the LED strip and sensors — step 8).
  • It must join your home Wi-Fi / LAN — the network Skypane is on (a guest or work network that can't reach the server won't do).
  • Your Manager open on a computer: http://192.168.1.50/admin/, signed in as the admin.
Since Skypane 3.0.2 a panel works only on the tablet you approved for it. The tablet shows a code, you approve it in the Manager, and it opens its own panel by itself from then on — even when its IP address changes. More: docs/panel-pairing.md.

1Connect the tablet to Wi-Fitablet

  1. Connect the tablet to the home Wi-Fi (or plug in PoE).
  2. A fixed IP address in your router isn't needed any more: the panel follows the tablet's key, not its address.

2Install FreeKiosktablet

  1. Install FreeKiosk (Google Play, or its official GitHub releases page) — the same kiosk app as the kitchen panel.
  2. Allow what it asks for (display over other apps, device admin / kiosk lock) so it can stay on screen.
Pair the tablet inside FreeKiosk (next steps), not in Chrome first: the panel's key lives in the browser that was approved.

3Point FreeKiosk at Skypanetablet

FreeKiosk settingSet it to
Start page / URLhttp://192.168.1.50/ — Skypane's own address. Before pairing it shows the code; after, it sends the tablet on to its panel.
Start on bootOn
Kiosk / lock modeOn (so the panel can't be swiped away)
Keep the screen onOn — Skypane keeps itself awake during tests and wakes the screen for alerts
Zoom / desktop modeOff (100 %) — Skypane measures the real screen and sizes itself
Setting names differ a little between FreeKiosk versions — look for these in its settings menu.

4Pair it: approve the codetablet + computer

  1. Restart FreeKiosk. The tablet shows Connect this panel with a 6-character code (e.g. K7M Q2X) and what it is (e.g. Chrome on Android, SM-T500). The code changes every 10 minutes; leave the screen open meanwhile.
  2. In the Manager: Panels → New panel requests → Approve next to that tablet.
  3. Type the code on the tablet (capitals or not, spaces don't matter) and a name: Office. The line under the name says Creates a new panel at /office. Press Approve.
    • Made the panel already (Panels → Add panel)? Type its name, or pick it under Or take over: — the tablet takes over that panel with its settings.
    • A panel that already has a tablet is refused: Unlink device on it first (step 7), or choose another name.
  4. The tablet says Connected as Office, shows http://192.168.1.50/office and opens it after a few seconds. A brand-new panel starts blank: an empty Home page with only the settings gear, no LED strip — you fill it in step 6.
Nothing under New panel requests? Accept new panels (the switch on that box) must be on — otherwise the tablet says Pairing is closed. And the request lasts only while the tablet shows the code.

5Connect FreeKiosk's extras (MQTT)tablet + computer

This lets Skypane turn the screen on and off, set the volume, speak alerts and pop up cameras on this tablet.

  1. Manager: Integrations → Message broker → Login for devices → use Copy user and Copy password (the password is never typed by hand).
  2. Manager: Panels → Setup → Office → General → Set up the tablet: note its FreeKiosk device name (e.g. office). Every tablet needs its own name.
  3. In FreeKiosk → MQTT:
    Broker192.168.1.50   port 1883
    Usernamepaste it from the Manager
    Passwordpaste it from the Manager
    Device namethe FreeKiosk name from above (e.g. office)
  4. Check the version tag in the panel's lower-left corner matches the one in the Manager's sidebar.
Keep that password to yourself — it can switch things through the broker. Don't paste it into chats, forums or screenshots.

6Make it its owncomputer

Everything is per panel, in Panels → Setup → Office. Changes wait in a bar at the bottom (2 changes waiting) until you press Save; then they go to the panel at once.

  • Look & layout — theme, background, room bar, and the builder for its Home page and room pages (or start from a built-in layout, or copy another panel's).
  • Rooms & devices — which rooms show, extra devices from other rooms, the order.
  • Cameras, People & calendars, Guest Wi-Fi card, Weather effects.
  • Safety (admin) — the panel PIN for every panel, how long it stays unlocked, and whether this panel may unlock locks.
  • Run the benchmark once (Weather effects) with the tablet on — it picks how heavy the weather effects can be on this tablet.

Then on the tablet: tap a light to test. Anything that needs the panel PIN (garage, unlocking, Settings) asks for the same PIN as the other panels.

The Hubitat Skypane Notifier driver targets panels by name — after adding Office you can send alerts or spoken messages to it (or "all").

7Later: replacing or moving a tabletcomputer

In Panels → Setup → Office, the Its tablet card shows the device, its last IP, when it was last seen and when it was paired:

  • Unlink device — the tablet loses its key; Office keeps its name and settings and waits, unclaimed. Pair the new tablet with the name Office and it takes over.
  • Move this device to… — this tablet takes over another, unclaimed panel.
  • Rename — only the name; the address and FreeKiosk name stay.

8Only for the same PoE wall-tablet model: LED strip & sensorsoptional

The kitchen panel runs a small panel agent for its LED strip and built-in sensors. A second panel of the same model can run it too. It needs adb (developer options → USB/network debugging) once; root is not needed since Skypane 3.0.5 (without root the agent is started again over adb after a reboot). The full steps, with and without root: docs/guides/led-agent.html (in the Manager: Help & guides → The LED agent). In short:

  1. Turn on network debugging on the new panel and note its address (e.g. 192.168.1.61:5555).
  2. Manager → Help & guides → The LED agent → Download the LED agent, and unzip it.
  3. Without root: push panel-agent, start-agent-noroot.sh and install-agent-noroot.sh to /data/local/tmp, run sh /data/local/tmp/install-agent-noroot.sh, and switch on LED agent without root for the panel. With root: push panel-agent, start-agent.sh and install-agent.sh, run su 0 sh /data/local/tmp/install-agent.sh, and install panel-agent-boot.apk so the agent starts after a reboot.
  4. Nothing more for the broker: with the built-in broker the panel page sets the agent up by itself (its name, the broker, the devices login), through the agent's port on the tablet itself (852 with root, 8852 without). The agent keeps its own MQTT settings, apart from FreeKiosk's (step 5), and updates itself from Skypane. Within a minute Panels → Setup → Office → Its tablet shows LED agent: Connected. A separate broker: write agent.args by hand (docs/panel-agent.md).
  5. On this tablet, open Skypane by its IP address (e.g. http://192.168.1.50/), not by a name: the agent connects to the broker at the address the page was opened with.
  6. Manager → Panels → Setup → Office → General → This tablet: switch LED strip on (new panels start with it off).
  7. Manager → Panels → Setup → Office → Alerts: choose This tablet's own light (or any Hubitat light) as the notification light.

Troubleshooting

What you seeTry
Blank page / can't connectIs the tablet on the home Wi-Fi? Can it open http://192.168.1.50/ in a browser?
"Pairing is closed"Switch Accept new panels on (Panels, the New panel requests box). The tablet asks again by itself.
"That isn't the code on the tablet"Type the code the tablet shows now (it renews every 10 minutes; no 0, O, 1 or I). 5 wrong codes cancel the request — the tablet then asks with a new one.
The tablet isn't under New panel requestsIt left the pairing screen or went to sleep. Wake it and reload http://192.168.1.50/.
"Unable to connect. This panel is connected to another device"Office already has a tablet. On this one, press Connect this device and approve it — after Unlink device on Office if this tablet should have it.
The pairing screen again, after it workedThe tablet's browser data was cleared (or FreeKiosk reinstalled): the key is gone. Unlink device on Office, then approve the tablet with the name Office — its settings are kept.
Screen on/off, volume or spoken alerts don't reach itStep 5: broker address, login, and the FreeKiosk device name must match the panel's.
Older version tag than the ManagerTap the Refresh pill if it shows, or restart FreeKiosk.
Effects stutterRun the benchmark (step 6), or lower Weather effects for this panel.

Checklist

  • Tablet on the home Wi-Fi
  • FreeKiosk: start page http://192.168.1.50/, start on boot, kiosk mode, screen on
  • Code approved in Panels → New panel requests; the tablet opened its panel
  • FreeKiosk MQTT: broker, devices login, device name
  • Loads, version tag matches, a light switches
  • Rooms, layout, cameras, people set for this panel and saved; benchmark run
  • (PoE model) panel agent (with root: + boot app; without root: the setting on), LED strip as the notification light
