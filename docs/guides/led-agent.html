Put the LED agent on a PoE wall tablet

A one-time job, about 20 minutes. After this, Skypane sets the agent up by itself and the agent updates itself. In this guide Skypane is at http://192.168.1.50:8088/ and the tablet at 192.168.1.61; use your own.

0Who needs this, and what you need

Only the PoE wall tablet with a built-in LED strip (the light bar around the screen) and its own sensors. A small program, the LED agent, drives the strip and reads the sensors. Any other tablet doesn't need it: skip this guide.

  • The tablet, already showing its Skypane panel (paired in the Manager).
  • A computer (Windows, Mac or Linux) and a USB cable, or the computer on the same network.
  • Skypane 3.0.5 or newer, with its built-in message broker.

Without root

Works on every tablet. The agent runs as adb's own user. After a reboot you run one start line again (step 7). The LED strip works only if the tablet lets adb use it (step 6 tells).

With root

For a rooted tablet. The agent runs as root. After a reboot, one start line starts it again (step 7) — or, once it is shipped, the optional boot app does that by itself.
Already there and the Manager says LED agent: Connected with version 4 or newer? You're done: it updates itself.

1Turn on developer modetablet

  1. Leave the panel (FreeKiosk's exit, with its PIN), then open Settings.
  2. Go to About tablet (on some tablets: System → About).
  3. Tap Build number 7 times, until it says You are now a developer! It may ask for the screen PIN.
No Build number? Look inside Software information: it's sometimes one level deeper.

2Turn on USB or network debuggingtablet

  1. Open Settings → System → Developer options (new since step 1).
  2. With a cable: switch on USB debugging. Over the network: switch on ADB over network (or Network debugging) and note the address it shows, e.g. 192.168.1.61:5555.
Debugging lets a computer control the tablet. ADB over network is the risky one: while it is on, anyone on your network can connect to the tablet on port 5555 and control it fully (install apps, read its files, the agent's login too). So use USB debugging with a cable when you can. If you use ADB over network, switch it off as soon as you're done (step 9) — without root too: for the start line after a reboot (step 7), switch it on just for that, or use a cable. With root, turn debugging off completely at the end.

3Install adb on your computercomputer

adb is Google's free tool for Android (part of "SDK Platform-Tools"). In a terminal:

Windowswinget install Google.PlatformTools — then open a new terminal.
Macbrew install android-platform-tools
Linuxsudo apt install adb (Fedora: sudo dnf install android-tools)

No package manager? Download SDK Platform-Tools from Google's Android developer site and unzip it. Check it works: adb version.

4Connect to the tablettablet + computer

adb connect 192.168.1.61:5555
adb devices

(With a cable, just adb devices.) The tablet asks Allow USB debugging?: tick Always allow from this computer and tap Allow. adb devices must then say device, not unauthorized.

5Get the agent filescomputer

  1. In the Manager: Help & guides → The LED agent → Download the LED agent. You get skypane-led-agent.zip; it always matches your Skypane.
  2. Unzip it and open a terminal in the skypane-led-agent folder (Windows: right-click inside the folder → Open in Terminal).

6Install the agentcomputer

Without root

adb push panel-agent start-agent-noroot.sh install-agent-noroot.sh /data/local/tmp/
adb shell sh /data/local/tmp/install-agent-noroot.sh

It ends with panel-agent running without root and a line about /dev/ledjni:

It saysWhat it means
crw-rw-rw- …The strip works without root.
crw-rw---- or crw------- …The tablet keeps the strip for root (or the system). The sensors still work; for the strip, use the root steps.
no /dev/ledjniThis tablet has no LED strip driver.

Then in the Manager: Panels → Setup → (this panel) → General → This tablet: switch on LED agent without root and press Save. (Without it the panel looks for the agent on port 852, where only a root agent can listen.)

With root

adb push panel-agent start-agent.sh install-agent.sh /data/local/tmp/
adb shell su 0 sh /data/local/tmp/install-agent.sh

If the tablet asks to give Shell superuser access, tap Grant. Leave LED agent without root off.

The Panel Agent Boot app (optional) starts the root agent after every reboot by itself. It isn't shipped with Skypane yet, so the zip doesn't have it; when a later zip has panel-agent-boot.apk, install it with adb install panel-agent-boot.apk. Until then, use the start line after a reboot (step 7).

7After a rebootcomputer

Without root nothing can start the agent by itself after the tablet restarts (with root neither, until the optional boot app is shipped). Run this once each time, with a cable or with ADB over network switched on just for it:

adb shell sh /data/local/tmp/skypane-agent/start-agent-noroot.sh

With root: adb shell su 0 sh /data/adb/panel-agent/start-agent.sh.

If a new build the agent updated itself to stops within 10 seconds of starting, the start line goes back to the one before (panel-agent.old) and says so in the agent's log.
Its settings and its token stay on the tablet, so it connects again at once. The Manager says LED agent: Not found on this tablet while it isn't running.

8In the Manager: the name and the stripcomputer

On this tablet, open Skypane by the server's IP address (http://192.168.1.50:8088/), not by a name such as skypane.local: the agent connects to the address the panel was opened with.

9Check it workedtablet + computer

  1. Go back to the panel on the tablet (restart FreeKiosk, or wait for its next reload).
  2. Within a minute Panels → Setup → (this panel) → Its tablet shows LED agent: Connected and its version.
  3. Turn ADB over network off again (Settings → System → Developer options). With root, turn USB debugging off too. Without root, keep only USB debugging if you can, for the start line after a reboot.

Updates: the agent does them itself

  • About every 6 hours (and a few minutes after it starts) the agent asks the Skypane that first set it up whether there is a newer agent. It asks only that Skypane, with its own token, and follows no other address. That address is fixed at the first set-up and never changes by itself (to move it, reset the agent on the tablet: see Troubleshooting).
  • Each update offer is signed with a key of this agent's own, which Skypane gave it once at the first set-up. The agent checks the signature before it downloads anything.
  • A new build is checked before it runs: its size and sha256 (from the signed offer), that it is a program for this tablet, and that it starts and says the version Skypane promised. Only then does it replace the old one (kept as panel-agent.old) and restart in place.
  • This works with and without root. Its tablet says update available while the agent is older than Skypane's. An agent from before Skypane 3.0.5 (version 3) can't update itself: put the new one on once with step 6.

The agent's port: only the real agent gets the login

Without root the agent listens on port 8852, which any app on the tablet could open while the agent isn't running. So before the panel hands the agent the broker login or its token, it asks it a question only the real agent can answer (a fresh challenge from Skypane, answered with the agent's own key).

If Its tablet says something answers on the LED agent's port but couldn't prove it is this tablet's agent, the panel sent it nothing. Check the tablet for an app you don't know, then start the agent again (step 7). If you reinstalled or reset the agent on purpose, unlink the tablet in the Manager and pair it again: the agent then gets a new key.

Troubleshooting

What you seeWhy, and what to do
LED agent: Not found on this tabletIt isn't running (without root: after a reboot, step 7), or it's older than Skypane 3.0.2. Without root, check LED agent without root is on for the panel. Read its log: adb shell cat /data/local/tmp/skypane-agent/panel-agent.log (with root: adb shell su 0 cat /data/adb/panel-agent/panel-agent.log).
Connected, but the strip stays darkLED strip is off for this panel (step 8), or without root the tablet keeps the strip for root (step 6's check).
Connected, but the wrong tablet reactsThe FreeKiosk device names don't match (step 8). Every tablet needs its own.
LED agent: Not connectedIt runs but can't reach Skypane's broker yet. Wait 5 minutes, check Manager → Health, and open Skypane by its IP address on the tablet.
Not connected for good, or no updates, after moving SkypaneThe agent still belongs to the old server (its update address and key never change by themselves). Reset it on the tablet — without root: adb shell rm -f /data/local/tmp/skypane-agent/agent.token /data/local/tmp/skypane-agent/agent.args /data/local/tmp/skypane-agent/agent.server /data/local/tmp/skypane-agent/agent.key, then step 7; with root: the same files in /data/adb/panel-agent with su 0, then adb shell su 0 sh /data/adb/panel-agent/start-agent.sh.
unauthorized in adb devicesAnswer Allow USB debugging? on the tablet (step 4).
su: not foundThe tablet has no root: use the steps without root.

Checklist

  • Developer mode and USB / network debugging on
  • adb on the computer; adb devices says device
  • Agent installed (without root: the /dev/ledjni check read; LED agent without root switched on)
  • ADB over network off again (USB debugging only, if you need it for the start line)
  • FreeKiosk name matches; LED strip on; Skypane opened by IP on the tablet
  • Its tablet: LED agent: Connected, with its version
